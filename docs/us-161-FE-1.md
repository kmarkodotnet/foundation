## Story

> As an **adminisztrátor**, I want to assign roles to users.

---

## Scope

Inline role selector on each user row in the Users list. Confirmation for role changes. Error handling for last-Admin guard.

---

## Implementation Checklist

### Feature Module
- [ ] `UsersPageComponent` — soronként „Szerepkör módosítása":
  - MatSelect: Admin / Elnök / Pályázati munkatárs / Pénzügyes / Megtekintő
  - Változás megerősítő dialog: „Biztosan módosítod a szerepkört?"
  - 422 hiba: error toast „Nem távolítható el az utolsó Admin szerepköre."

### Service
- [ ] `UserService.assignRole(userId: string, role: string): Observable<UserListItemDto>` — PUT /api/v1/users/:id/role

### State / Data Flow
- [ ] Sikeres módosítás: helyi lista frissítése, toast „Szerepkör módosítva."

## API Consumed

## Acceptance Criteria

- [ ] **AC1**: A felhasználó sorából elérhető a „Szerepkör módosítása" opció (inline MatSelect vagy menü-megnyitás).
- [ ] **AC2**: A szerepkör legördülő listából választható: Admin, Elnök, Pályázati munkatárs, Pénzügyes, Megtekintő. CR2 utáni állapotban a Foundation-scope szerepkörök CR2.5 FoundationRole enum-jából (FoundationAdmin/Elnok/PalyazatiMunkatars/Penzugyes/Megtekinto).
- [ ] **AC3**: Mentés után a változás azonnal életbe lép szerver-oldalon (a backend `IAuditLogger` audit-bejegyzést készít, a felhasználó következő oldalbetöltésekor az új JWT-vel kapja az új jogosultságokat). A FE az aktuális JWT-t **nem** invalidálja; az érintett felhasználó újra-bejelentkezésekor érvénybe lép.
- [ ] **AC4**: Legalább 1 aktív Admin felhasználónak mindig lennie kell: az utolsó Admin szerepkörének eltávolítása 422-vel elutasított; a UI error toast: „Nem távolítható el az utolsó Admin szerepköre." (lásd us-161-BE-1).
- [ ] **AC5**: A módosítás audit-bejegyzéssel jár (backend felelőssége — `FOUNDATION_ROLE_CHANGED` művelettípus, lásd us-233-BE-1). A FE a sikeres mentés snackbar-jában visszajelzi: „Szerepkör módosítva. (Auditba elmentve)" — opcionális szubtilis indikátor.
