# us-162-FE-1 | FE: Activate/Deactivate User

**Story:** US-162 | [Admin] Felhasználó inaktiválása és reaktiválása  
**Layer:** Frontend  
**Priority:** Közepes  
**Size estimate:** S  
**Sprint:** Sprint 2  
**Depends on:** us-162-BE-1.md, us-160-FE-1.md  
**Blocks:** —

---

## Story

> As an **adminisztrátor**, I want to deactivate or reactivate users.

---

## Scope

Deactivate/reactivate button on each user row. Self-deactivation attempt shows error. Inactive users visually greyed out.

---

## Implementation Checklist

### Feature Module
- [ ] `UsersPageComponent` — soronként:
  - „Inaktiválás" gomb (ha isActive=true, `*hasRole="['Admin']"`, hidden for currentUser)
  - „Reaktiválás" gomb (ha isActive=false)
  - ConfirmDialog: „Biztosan inaktiválod [Felhasználó neve]?"
  - 422 hiba (saját fiók): error toast „Saját fiókod nem inaktiválhatod."

### Service
- [ ] `UserService.deactivateUser(userId: string): Observable<UserListItemDto>` — PATCH /api/v1/users/:id/deactivate
- [ ] `UserService.activateUser(userId: string): Observable<UserListItemDto>` — PATCH /api/v1/users/:id/activate

### State / Data Flow
- [ ] Sikeres inaktiválás: felhasználó szürkítve jelenik meg
- [ ] Toast „Felhasználó inaktiválva." / „Felhasználó reaktiválva."

---

## Acceptance Criteria

- [ ] **AC1**: A felhasználó sorában elérhető az „Inaktiválás" / „Reaktiválás" gomb (állapot-vezérelt megjelenítés).
- [ ] **AC2**: Inaktivált felhasználó bejelentkezési kísérletekor a UI a backend 403 választ kezeli és a `login.component`-en hibaüzenetet jelenít meg: „A fiókod jelenleg inaktív. Kérjük, vedd fel a kapcsolatot az adminisztrátorral."
- [ ] **AC3**: Admin nem inaktiválhatja saját fiókját — a gomb a saját során **nem látható** (`*ngIf="!user.isSelf"`). Ha valamilyen edge case-ben mégis meghívódik a 422 backend válasz: error toast „Saját fiókod nem inaktiválhatod."
- [ ] **AC4**: Inaktivált felhasználó adatainak megőrzése — a UI továbbra is **megjeleníti** a felhasználó által írt megjegyzéseket (a `gm-comment` komponens szürkített „Inaktív felhasználó" badge-dzsel), és a feltöltött dokumentumokat (a `gm-document` listán az inaktív feltöltő `(inaktív)` szöveggel kiegészített név). Az adatok nem törlődnek.
- [ ] **AC5**: Az inaktiválás és reaktiválás audit-bejegyzéssel jár (backend felelőssége — meglévő `USER_DEACTIVATED`/`USER_REACTIVATED` művelettípusok). A FE a snackbar visszajelzésével ezt jelzi: „Felhasználó inaktiválva. (Auditba elmentve)".
