## Scope

Az Owner részletező oldalon a „Felfüggesztés" / „Reaktiválás" gombok állapot-vezérelt megjelenítése és a megerősítő dialog.

---

## Implementation Checklist

### Feature Module (`src/app/features/platform/owners/`)
- [ ] `owner-details.component.ts` bővítése:
  - „Felfüggesztés" gomb: csak ha `status === 'Active'`
  - „Reaktiválás" gomb: csak ha `status === 'Suspended'`
  - Mindkét gomb PlatformAuditor-nál rejtett (`*hasRole`)
- [ ] `owner-suspend-confirm-dialog.component.ts` — megerősítő dialog (destructive action)
- [ ] `PlatformOwnerService` bővítése: `suspend(id: string)`, `reactivate(id: string)` metódusok

### State / Data Flow
- [ ] Sikeres felfüggesztés → snackbar „Owner felfüggesztve." + oldal frissítés (státusz badge frissül)
- [ ] Sikeres reaktiválás → snackbar „Owner reaktiválva."
- [ ] Megerősítő dialog: „Biztosan felfüggeszted? A felhasználók nem tudnak majd bejelentkezni."

---

## API Consumed

| Method | URL | Response |
|---|---|---|
| `POST` | `/api/v1/platform/owners/:id/suspend` | `{ status }` |
| `POST` | `/api/v1/platform/owners/:id/reactivate` | `{ status }` |

---

## UX / Behaviour

| Scenario | Expected behaviour |
|---|---|
| ACTIVE Owner, PlatformAdmin | „Felfüggesztés" gomb látható és aktív |
| SUSPENDED Owner, PlatformAdmin | „Reaktiválás" gomb látható; „Felfüggesztés" rejtett |
| PlatformAuditor | Egyik gomb sem látható |
| Megerősítés nélkül | Semmi sem történik, dialog bezárul |

## Acceptance Criteria

- [ ] **AC1**: Az Owner részletes oldalán a „Felfüggesztés" gomb csak `ACTIVE` állapotnál, a „Reaktiválás" gomb csak `SUSPENDED` állapotnál látható és aktív (state-aware megjelenítés). PlatformAuditor szerepkörnél egyik gomb sem látható.
- [ ] **AC2**: Felfüggesztett Owner-hez tartozó felhasználó bejelentkezési kísérletekor a UI a `403` választ kezeli és a hibaüzenetet megjeleníti: „A szervezeted hozzáférése jelenleg fel van függesztve." (lásd `login.component.ts` bővítés).
- [ ] **AC3**: A felfüggesztés idején a UI nem mutat semmilyen adatvesztés-jelet (az Owner részletek továbbra is olvashatók, csak a státuszbadge változik `SUSPENDED`-re).
- [ ] **AC4**: Reaktiválás után a státuszbadge `ACTIVE`-ra változik, és a felhasználók a következő bejelentkezéskor új JWT-vel hozzáférnek (UI-szintű visszajelzés: snackbar „Owner reaktiválva.").
- [ ] **AC5**: Mindkét művelet után a snackbar visszajelzés tartalmazza, hogy a műveletről audit-bejegyzés készült (a backend felelőssége; lásd us-201-BE-1).
