## Story

> As an **OwnerAdmin**, I want to create a new foundation under my Owner, so that I can start managing a new organizational unit in the system.

---

## Scope

`Foundation.Create()` domain logika, `CreateFoundationCommand` handler, az Owner-szintű kódszótár-sablon snapshot másolása, opcionális Granter/Vendor template-másolás és az initiális FoundationAdmin meghívó kiállítása.

---

## Implementation Checklist

### Application Layer (`GrantManagement.Application`)
- [ ] `CreateFoundationCommand`: `Application/OwnerAdministration/Foundations/Commands/CreateFoundation/`
  - `Name: string`, `LogoFile?: IFormFile`, `InitialFoundationAdminEmail: string`, `TemplateFoundationId?: Guid`
  - Implementálja `IScopedRequest` (audience = `owner`)
  - Multipart/form-data támogatás a logó upload miatt (vagy külön logó-upload endpoint, lásd alább)
- [ ] `CreateFoundationCommandHandler`:
  1. Validálja: Owner `Status == Active` (a domain invariáns is dobja, de korai validáció jobb UX)
  2. Ha `TemplateFoundationId != null`: validálja, hogy a sablon-Foundation ugyanazon Owner-hez tartozik (`Foundation.OwnerId == _scope.OwnerId`); ha nem → `DomainException` (NK-15 invariáns).
  3. `Foundation.Create(ownerId, name, logoUri, templateFoundationId)` (lásd `domain-model.md` CR2.2.2) — `FoundationCreated` domain esemény
  4. **Owner-szintű kódszótár-sablon** snapshot másolása az új Foundation `CodeList`-jébe (NK-16 — `OwnerCodeListTemplate.ApplyToNewFoundation()` hívás, lásd `domain-model.md` CR2.2.4)
  5. **NK-15 sablon-másolás (AC4)**: ha `TemplateFoundationId != null`, az `IFoundationTemplateCloneService` aktív `Granter` és `Vendor` aggregátumokat snapshot-elve (új `Id`, új `FoundationId`, ugyanazok az egyéb mezők) létrehozza az új Foundation-ban. Csak `Status == Active` rekordok kerülnek átmásolásra.
  6. Foundation-scope meghívó: az új `Invitation` aggregátum (lásd `domain-model.md` CR2.2.5) → `Invitation.IssueFoundation(email, newFoundationId, FoundationRole.FoundationAdmin, _currentUser.Id)`. E-mail küldés a `IEmailService.SendInvitationAsync(...)` hívással.
  7. **Kettős audit (AC6)**: `FOUNDATION_CREATED` művelettípussal egy bejegyzés az Owner-szintű naplóba (`OwnerId = newOwnerId, FoundationId = NULL`) **és** egy bejegyzés a Foundation-szintű naplóba (`OwnerId = newOwnerId, FoundationId = newFoundationId`). Ezt az `IAuditLogger` interfész egy új `LogToBothLevels(...)` extension metódusa biztosítja.
- [ ] `CreateFoundationCommandValidator`: `Name.NotEmpty().MaximumLength(200)`, `InitialFoundationAdminEmail` valid email, `LogoFile`: MIME ∈ {image/png, image/jpeg, image/svg+xml, image/webp}, méret ≤ 2 MB
- [ ] `GetFoundationsListQuery` + Handler: Owner alá tartozó Foundation-ok listázása
- [ ] `FoundationListItemResponse` DTO: `{ Id, Name, Status, LogoUri, CreatedAt, ActiveApplicationsCount }`
- [ ] **Új service**: `IFoundationTemplateCloneService` interfész + implementáció: NK-15 sablonalapítvány Granter+Vendor másolás. Method: `Task CloneTemplateContentAsync(Guid templateFoundationId, Guid newFoundationId)`.

## API Contract

### POST /api/v1/owner/foundations
**Auth:** `IsOwnerAdmin`

**Request:**
```json
{
  "name": "Béta Alapítvány",
  "logoUri": null,
  "initialFoundationAdminEmail": "admin@betaalapitv.hu",
  "templateFoundationId": null
}
```

**Response 201:** `{ "id": "...", "name": "Béta Alapítvány", "status": "Active" }`  
**400** — Validációs hiba  
**422** — Owner nem ACTIVE állapotban

---

## FluentValidation Rules

| Field | Rule | Error |
|---|---|---|
| `Name` | `NotEmpty().MaximumLength(200)` | "Az alapítvány neve kötelező." |
| `InitialFoundationAdminEmail` | `NotEmpty().EmailAddress()` | "Érvényes FoundationAdmin e-mail szükséges." |
| `TemplateFoundationId` | Custom: ha megadott, az adott Foundation az aktuális Owner-hez tartozik | "A sablon-alapítvány nem ehhez az Owner-hez tartozik." |
