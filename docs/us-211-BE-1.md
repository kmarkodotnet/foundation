## Scope

`Foundation.Archive()` domain logika (aktív Application-ok ellenőrzése), az OwnerAdmin archiváló command és a Foundation felhasználó-hozzárendelések automatikus inaktiválása.

---

## Implementation Checklist

### Application Layer (`GrantManagement.Application`)
- [ ] `ArchiveFoundationCommand`: `Application/OwnerAdministration/Foundations/Commands/ArchiveFoundation/` — `FoundationId: Guid`
- [ ] `ArchiveFoundationCommandHandler`:
  1. `IApplicationCountService.GetActiveCount(foundationId)` — ha > 0: `DomainException("N aktív pályázat van; először zárd le őket.")`
  2. `Foundation.Archive()` — `FoundationArchived` esemény
  3. **Kaszkád inaktiválás (AC3)**: `FoundationUserAssignment.IsActive = false` és `RevokedAt = now` az összes, az adott Foundation-hoz tartozó hozzárendelésre (bulk update). Minden inaktivált hozzárendelésről külön `FoundationAssignmentRevoked` esemény, audit-bejegyzés `FOUNDATION_ASSIGNMENT_REVOKED` `details = { reason: "FoundationArchived" }`.
  4. **JWT invalidálás**: az érintett felhasználók aktív JWT-it a `CurrentScopeService` cache-szel max 60s-en belül `FoundationAssignment.IsActive` újraellenőrzéssel érvényteleníti.
  5. Audit: `FOUNDATION_ARCHIVED` `details = { archivedCount: N, revokedAssignmentCount: M }`

### Domain Layer (`GrantManagement.Domain`)
- [ ] `Foundation.Archive()`: csak `ACTIVE` állapotnál; `ARCHIVED`-re állítja; `FoundationArchived` esemény; az Application-ellenőrzést a domain service végzi (`IApplicationCountService`).
- [ ] `Foundation.Archive()` automatikusan kiváltja a kaszkád eseményt (a domain event handler az application service-ben végzi a hozzárendelés-inaktiválást).

### Break-glass / Owner audit olvasás archivált Foundation-ra (AC4)
- [ ] `GetArchivedFoundationDetailsQuery` (`Application/OwnerAdministration/Foundations/Queries/GetArchivedFoundationDetails/`):
  - `[ScopeBypassAllowed("Reading archived foundation in Owner audit context")]` attribútum
  - Handler `IgnoreQueryFilters()` használja, de **kötelező** `OwnerId == _scope.OwnerId` explicit filter
  - Csak akkor enged át, ha (a) az Owner-szintű audit-napló kontextusból érkezik a kérés, **vagy** (b) van érvényes `BreakGlassGrant` az adott Owner-re
- [ ] `FoundationsController` új végpont: `GET /api/v1/owner/foundations/{id}/archived-details` — `[Authorize(Policy = "CanReadOwner")]`; archív Foundation olvasási hozzáférés.
- [ ] Break-glass JWT (`break_glass_grant_id` claim) esetén az archív Foundation üzleti aggregátumai (Applications, Documents, stb.) is elérhetők — a meglévő `IgnoreQueryFilters()` whitelist callsite-ok kiterjesztése a break-glass audience-ekre.
- [ ] Integration teszt: archív Foundation `GET /api/v1/applications` — break-glass JWT nélkül 404; break-glass JWT-vel 200, csak az érintett Owner alapítványai elérhetők.

### API Layer (`GrantManagement.API`)
- [ ] `FoundationsController` bővítése: `POST /api/v1/owner/foundations/{id}/archive` — `[Authorize(Policy = "IsOwnerAdmin")]`

---

## API Contract

**POST /api/v1/owner/foundations/{id}/archive**  
Auth: `IsOwnerAdmin`  
**200:** `{ "status": "Archived" }`  
**400:** `"3 aktív pályázat van; először zárd le őket."` (aktív Application)  
**403:** Foundation más Owner-é (scope mismatch)  
**404:** Foundation nem létezik
