## Story

> As a **rendszer**, I want JWT tokens issued with three-level scope and audience separation, so that vertical privilege escalation is architecturally impossible.

---

## Scope

Megvalósítja az új `ICurrentScopeService`-t, a bővített JWT claim-kiállítást (scope, owner_id, foundation_id, platform_role, owner_role, foundation_roles, break_glass_grant_id) és a háromféle `audience` (`platform`/`owner`/`business`) szétválasztást. Tartalmazza az `available-scopes` végpontot is. **Nem** tartalmaz UI-t (az FE-tevékenység az us-220-FE-1-ben).

public interface ICurrentScopeService
{
    string Audience { get; }                  // "platform" | "owner" | "business"

### Infrastructure Layer (`GrantManagement.Infrastructure`)
- [ ] `CurrentScopeService`: `Infrastructure/Auth/CurrentScopeService.cs` — implementálja `ICurrentScopeService`-t; JWT claim-ekből olvassa a scope-ot `IHttpContextAccessor` segítségével; `CanAccessOwner()` validálja a `break_glass_grant_id`-t is (`BreakGlassGrants` tábla lekérdezéssel)
- [ ] `JwtTokenService` bővítése: `Infrastructure/Auth/JwtTokenService.cs`

- [ ] `GoogleLoginCommandHandler` bővítése: a Google callback után meghatározza az initial audience-t és a megfelelő scope-ot, majd az új `GenerateTokenForScope()`-ot hívja
- [ ] DI regisztráció: `ICurrentScopeService → CurrentScopeService` (Scoped)

### API Layer (`GrantManagement.API`)
- [ ] `ScopeSwitchController`: `API/Controllers/Me/ScopeSwitchController.cs`
  - `POST /api/v1/me/scope-switch` — `[Authorize]`, `ScopeSwitchCommand`, visszaad új JWT-t
  - `GET /api/v1/me/available-scopes` — `[Authorize]`, `GetAvailableScopesQuery`
- [ ] `Program.cs` JWT validation frissítése: `ValidateAudience = true`; az audience értékek: `["platform", "owner", "business"]`; végpont-csoportonként külön `[Authorize(Policy = ...)]` ami audience-t is vizsgál
- [ ] Új authorization policies `Program.cs`-ben:
  - `IsPlatformAdmin`: audience = `platform`, platform_role = `PlatformAdmin`
  - `CanReadPlatform`: audience = `platform`
  - `IsOwnerAdmin`: audience = `owner`, owner_role = `OwnerAdmin`
  - `CanReadOwner`: audience = `owner`
  - `CanManageFoundations`: audience = `owner`, owner_role = `OwnerAdmin`
  - `CanIssueBreakGlass`: audience = `platform`, platform_role = `PlatformAdmin`

## API Contract

### POST /api/v1/me/scope-switch
**Auth:** `[Authorize]` (bármely audience)

**Request:**
```json
{ "targetFoundationId": "3fa85f64-5717-4562-b3fc-2c963f66afa6" }
```

**Response 200:**
```json
{
  "accessToken": "eyJhbGci...",
  "expiresIn": 28800,
  "audience": "business",
  "foundationId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "foundationName": "Alfa Alapítvány"
}
```

**400** — Foundation nem elérhető a felhasználó számára  
**403** — Foundation más Owner-hez tartozik

### GET /api/v1/me/available-scopes
**Auth:** `[Authorize]`

**Response 200:**
```json
{
  "platformRole": null,
  "ownerId": "...",
  "ownerName": "Tulajdonos Kft.",
  "ownerRole": "OwnerAdmin",
  "foundations": [
    { "foundationId": "...", "foundationName": "Alfa Alapítvány", "role": "FoundationAdmin" },
    { "foundationId": "...", "foundationName": "Béta Alapítvány", "role": "Megtekinto" }
  ]
}
```

## Notes

- Az `appsettings.json`-ben szükséges: `Jwt:Audiences: ["platform", "owner", "business"]` és `Jwt:SecretKey` (aszimmetrikus kulcs RS256-ra frissítendő long-term, de MVP-re HS256 elfogadható).
- Ha egy felhasználónak több mint 50 Foundation hozzárendelése van, a `foundation_roles` claim helyett `roles_ref` kerül a JWT-be és szerver-oldali cache (in-memory Scoped) tartja a mappet — MVP-n belül ez nem várható.
