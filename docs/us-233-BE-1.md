## Story

> As a **rendszer**, I want every audit entry to automatically record the current scope and handle new CR2-specific operation types, so that the log is fully filterable at all three levels.

---

## Scope

Bővíti a meglévő `AuditLog` entitást `OwnerId`/`FoundationId` mezőkkel, az `AuditAction` enumot új CR2 művelettípusokkal, és frissíti az `IAuditLogger` implementációt a scope automatikus rögzítéséhez. A napló-lekérdező végpontok scope-szűrése szintén itt valósul meg.

---

## Implementation Checklist

### Domain Layer (`GrantManagement.Domain`)
- [ ] `AuditLog` entitás bővítése (`Domain/Entities/AuditLog.cs`): új nullable mezők `OwnerId (Guid?)`, `FoundationId (Guid?)`
- [ ] `AuditAction` enum bővítése (`Domain/Enums/AuditAction.cs`) — **a teljes, szinkron lista** az `architecture-plan.md` CR2.G és `domain-model.md` CR2.6 szerint:
  - Hatókör: `SCOPE_SWITCH`, `SCOPE_VIOLATION`
  - Break-glass: `BREAK_GLASS_ACCESS`, `BREAK_GLASS_REVOKED`, `BREAK_GLASS_EXPIRED`
  - Owner lifecycle: `OWNER_PROVISIONED`, `OWNER_SUSPENDED`, `OWNER_REACTIVATED`, `OWNER_ARCHIVED`
  - Foundation lifecycle: `FOUNDATION_CREATED`, `FOUNDATION_RENAMED`, `FOUNDATION_ARCHIVED`, `FOUNDATION_LOGO_UPDATED`
  - Kódszótár-sablon: `CODE_LIST_TEMPLATE_APPLIED`
  - Meghívók: `INVITATION_ISSUED`, `INVITATION_ACCEPTED`, `INVITATION_REVOKED`, `INVITATION_RESENT`, `INVITATION_EXPIRED`
  - Szerepkör-műveletek: `PLATFORM_ROLE_ASSIGNED`, `PLATFORM_ROLE_REVOKED`, `OWNER_ROLE_ASSIGNED`, `OWNER_ROLE_REVOKED`, `FOUNDATION_ASSIGNMENT_CREATED`, `FOUNDATION_ASSIGNMENT_REVOKED`, `FOUNDATION_ROLE_CHANGED`
  - Beállítások: `PLATFORM_SETTINGS_UPDATED`, `OWNER_SETTINGS_UPDATED`
  - Megőrzés/migráció: `AUDIT_ARCHIVED`, `DOCUMENT_FILEPATH_MIGRATED`

### Infrastructure Layer (`GrantManagement.Infrastructure`)
- [ ] `AuditLogConfiguration` frissítése: `OwnerId`, `FoundationId` nullable oszlopok, indexek `(OwnerId, FoundationId)`
- [ ] `AuditLogger` implementáció (`Infrastructure/Audit/AuditLogger.cs`) bővítése: minden `Log()` hívásnál automatikusan beállítja `OwnerId = _scope.OwnerId`, `FoundationId = _scope.FoundationId`; platform-szintű kontextusban ezek `null`-ok maradnak
- [ ] Migráció: `dotnet ef migrations add CR2_ExtendAuditLog` — `OwnerId`, `FoundationId` nullable oszlopok + `(OwnerId, FoundationId)` index

### Application Layer (`GrantManagement.Application`)
- [ ] `GetAuditLogsQuery` bővítése (`Application/AuditLogs/Queries/GetAuditLogs/`):
  - Automatikus scope-szűrés: Foundation audience → `FoundationId == _scope.FoundationId`; Owner audience → `OwnerId == _scope.OwnerId` (cross-foundation); Platform audience → nincs szűrés (platform-szintű napló)
  - Új filter paraméterek: `OwnerId?`, `FoundationId?`, `AuditAction?`
- [ ] `GetAuditLogsQueryHandler` frissítése: scope-alapú szűrőlogika
- [ ] `AuditLogListItemResponse` DTO bővítése: `OwnerId?`, `FoundationId?`, `OwnerName?`, `FoundationName?` mezők

## API Contract

### GET /api/v1/audit-logs (meglévő, bővített)

**Új query paraméterek:**

| Param | Típus | Leírás |
|---|---|---|
| `ownerId` | `Guid?` | Csak Owner/Platform scope-ban elérhető szűrő |
| `foundationId` | `Guid?` | Foundation megjelölése |
| `action` | `string?` | Pl. `SCOPE_SWITCH`, `BREAK_GLASS_ACCESS` |

```json
      "entityType": "Auth",

      "details": "Hatókör váltás: Alfa → Béta Alapítvány"
    }
  ],
  "totalCount": 42

```

### GET /api/v1/platform/audit-logs (új, us-205-BE-1-ben implementálva)
Auth: `CanReadPlatform` — platform-szintű napló, scope-szűrés nélkül, tartalmazza az összes Owner eseményét.

### GET /api/v1/owner/audit-logs (új, us-216-BE-1-ben implementálva)
Auth: `CanReadOwner` — csak az aktuális Owner alá tartozó alapítványok eseményei.

## Törlés-tilalom és megőrzési politika implementáció (AC5)

### Törlési tilalom mind a három szinten
- [ ] `AppDbContext.SaveChangesAsync` override-ban: `ChangeTracker.Entries<AuditLog>().Any(e => e.State == EntityState.Deleted)` esetén `InvalidOperationException("AuditLog rekordok nem törölhetők. Az archiválás kizárólag a AuditLogRetentionJob-on keresztül engedélyezett.")`.
- [ ] **NINCS** `[HttpDelete]` action sem a `PlatformAuditLogsController`, sem az `OwnerAuditLogsController`, sem az `AuditLogsController` (Foundation-szintű) controllerekben.
- [ ] NetArchTest szabály (`AuditLogIsNotDeletableTest`): a teljes codebase-ben az `AuditLog` típusra hivatkozó `Remove()` / `RemoveRange()` hívás csak az `AuditLogRetentionJob` osztály belsejében engedélyezett (whitelisted callsite).
- [ ] Integration teszt: `DELETE /api/v1/platform/audit-logs/{id}` → 404 (route not found); ugyanígy az Owner és Foundation szintű végpontokon.

### 5 éves megőrzés és archiválás
- [ ] Új tábla: `AuditLogsArchive` — ugyanaz a séma, mint `AuditLogs`, plus `ArchivedAt: DateTimeOffset`.
- [ ] Új Hangfire recurring job: `AuditLogRetentionJob` — napi futás (Cron `0 3 * * *`):
  - SELECT `AuditLog` WHERE `Timestamp < now - 5 év`
  - Tranzakcióban: INSERT into `AuditLogsArchive` + DELETE from `AuditLogs`
  - Audit-bejegyzés (`AUDIT_ARCHIVED`) a tranzakcióban: `details = { archivedCount: N, oldestArchivedTimestamp, newestArchivedTimestamp }`
- [ ] `Program.cs`-ben a job regisztráció: `RecurringJob.AddOrUpdate<AuditLogRetentionJob>("audit-log-retention", j => j.RunAsync(), "0 3 * * *");`
- [ ] Új query paraméter a Platform-szintű napló-végponton: `includeArchive: bool` (default `false`); ha `true`, az `AuditLogsArchive` is UNION-olva van.
- [ ] Integration teszt: a job kétszeri futtatása ugyanazon a napon ne dupla-archiváljon (idempotens — az archív tábla `PRIMARY KEY (Id)` constraint adja a védelmet).

## Notes

- `SCOPE_VIOLATION` auditálása az `AuthorizationBehaviour`-ből kell hogy jöjjön — a behaviour eldobja a `ForbiddenException`-t, de előtte audit-bejegyzést ír.
- A `BREAK_GLASS_ACCESS` és `BREAK_GLASS_EXPIRED`/`BREAK_GLASS_REVOKED` naplózás a `BreakGlassGrant` domain event handlereiből kerül ki (us-206-BE-1, us-207-BE-1).
